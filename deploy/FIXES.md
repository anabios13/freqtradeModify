# Исправления в системе FreqTrade

## Проблема с ограничением сделок (LIMIT 100)

### Описание проблемы

В `scripts/data_aggregator.py` было жестко задано ограничение `LIMIT 100` для загрузки сделок из баз данных стратегий. Это приводило к тому, что:

- Каждая стратегия показывала максимум 100 сделок
- Реальные данные о прибыльности были неполными
- Общая статистика была неточной

### Что было исправлено

1. **Убрано жесткое ограничение LIMIT 100** из SQL запросов
2. **Добавлен параметр `trades_limit`** в конструктор класса для гибкой настройки
3. **Добавлено логирование** количества загруженных сделок для каждой стратегии

### Результат исправления

**До исправления:**

- Общее количество сделок: 497
- Общая прибыль: 5.1079
- Win rate: 63.18%

**После исправления:**

- Общее количество сделок: 1060
- Общая прибыль: 5.9623
- Win rate: 57.08%

**Детали по стратегиям:**

- bandtastic: 494 сделки (было 100)
- rsi: 107 сделок (было 100)
- strategy001: 103 сделки (было 100)
- bandtastic_freqai: 259 сделок (было 100)
- highfreq_ai: 78 сделок (без изменений)
- freqai_example: 19 сделок (без изменений)

### Код исправления

#### Было:

```python
# Получаем последние 100 сделок
df = pd.read_sql_query(
    "SELECT * FROM trades ORDER BY close_date DESC LIMIT 100",
    conn
)
```

#### Стало:

```python
# Получаем сделки с возможным ограничением
query = "SELECT * FROM trades ORDER BY close_date DESC"
if self.trades_limit:
    query += f" LIMIT {self.trades_limit}"
df = pd.read_sql_query(query, conn)
trades_count = len(df)
strategy_data["data"]["trades"] = df.to_dict('records')
logger.info(f"Загружено {trades_count} сделок для стратегии {strategy_name}")
```

### Как использовать

Теперь можно настроить лимит сделок при создании агрегатора:

```python
# Загружать все сделки (по умолчанию)
aggregator = FreqTradeDataAggregator()

# Или ограничить количество
aggregator = FreqTradeDataAggregator(trades_limit=500)
```
